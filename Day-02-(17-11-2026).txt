TempData In ASP.NET Core MVC
-----------------------------
using EmployeeManagementSystem.Models;
using Microsoft.AspNetCore.Mvc;

namespace EmployeeManagementSystem.Controllers
{
    public class PassingDataController : Controller
    {
        public IActionResult Index()
        {
            return View();
        }

        public IActionResult Save()
        {
            TempData["Success"] = "Employee Save Successfully";

            return RedirectToAction("Index");
        }
    }
}

@if(TempData["Success"] != null)
{
    <div class="alert alert-success">
        @TempData["Success"]
    </div>
}

When Should We Use TempData?

* Use TempData for : 
	
	1. Save Success Message
	2. Delete Success Message
	3. Update Confirmation
	4. Login Success
	5. Logout Message

When Should We NOT Use TempData?
		
* Don't use TempData for :
	
	1. Employee Lists
	2. Product Lists
	3. Customer Details

Routing In ASP.NET Core MVC
---------------------------

* Routing is the process of mapping an incoming HTTP request to the appropriate Controller and Action Method.

https://localhost:5001/Employee/Details/101

Flow : Browser -> Kestrel Web Server -> Middleware Pipeline -> Endpoint Routing Middleware -> Controller Selection -> Action Selection -> Model Binding -> Controller Execution -> Business Logic -> Database -> Model Creation -> View Engine -> HTML Generation -> Browser

What is Conventional Routing?

* Its means all routing rules are written in one central place

Where is Conventional Routing Written? Program.cs

app.UseRouting()

Pattern : {controller}/{action}/{id}

Browser : /Employee/Details/101

Example :

using Microsoft.AspNetCore.Mvc;

namespace EmployeeManagementSystem.Controllers

        {
            return View();
        }

        public IActionResult Details(int id)

            return View();

Attribute Routing In ASP.NET Core MVC
--------------------------------------
* Attribute Routing is a routing technique where the route is defined directly on the Controller or Action Method using attributes.

Example : [Route("employee")] or [Route("employee/details/{id}")]

When Should We Use Attribute Routing?

Use Attribute Routing when :

	1. Different Controllers require different URL patterns
	2. REST APIs are being developed
	3. Business wants custom URLs
	
Example :

using Microsoft.AspNetCore.Mvc;

namespace EmployeeManagementSystem.Controllers
{
    [Route("employee")]
    public class EmployeeController : Controller
    {       
        public IActionResult Index()
        {
            return View();
        }

        [Route("details/{id}")]
        // /employee/details/101
        public IActionResult Details(int id)
        {
            ViewBag.Id = id;

            return View();
        }
    }
}

<h2>Employee Details</h2>

Employee Id : @ViewBag.Id

Advantages of Attribute Routing
-------------------------------
1. Route is close to the Action Method
2. Easy to maintain
3. Ideal for REST APIs
4. Supports custom URL structures
5. Reduces complexity in Program.cs

Sections In Layout View In ASP.NET Core MVC
-------------------------------------------

* A Section is a placeholder inside the Layout page where individual Views can insert their own content.

* A Section is used for page-specific content like :
		
	1. JavaScript
	2. CSS
	3. Charts
	4. Google Maps
	5. Custom Scripts
	6. Page-specific Footer Content

When Should we use Sections?

* Use Sections when :
		
	1. A page requires additional JavaScript.
	2. A page requires additional CSS
	3. A page requires charts
	4. A page requires  Google Maps
	5. A page requires page-specific scripts

Where are Sections used?

1. Employee Management 
2. Banking
3. Hospital
4. Amazon

Syntax : 

Inside Layout : @RenderSectionAsync("Scripts", required : false)	

Inside View : @section Scripts{}

View State In ASP.NET Core MVC
------------------------------
* View State automatically stores the values of controls like :
	
	1. TextBox
	2. DropDownList
	3. CheckBox
	4. RadioButton
	
Does ASP.NET Core MVC supports View State? NO

ASP.NET Core MVC does not support View State.

Microsoft completely removed View State from ASP.NET Core MVC.

Why was View State removed?

* View State had several disadvantages :
	
	1. Large Page Size
	
	2. Increased Network Traffic
	
	3. Performance Issues

How do we maintain data in ASP.NET Core MVC?

* Instead of View State, MVC uses other techniques :
		
	1. Model Binding
	2. Hidden Fields
	3. TempData
	4. Session
	5. Cookies
	6. Query String
	7. Database
